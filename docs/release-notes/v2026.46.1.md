# Open Calc Studio 2026.46.1

Released on 11 November 2026. Product version **2026.46.1**,
Windows MSI **26.46.1**, native project format **2.4.0** (unchanged).

## PDFs load again in the web version — #80

- The PDF.js worker is now emitted as `pdf.worker.min-*.js` instead of `.mjs`.
  Web servers without `.mjs` in their MIME table (such as a default nginx)
  served it as `application/octet-stream`; the browser refused the module
  script ("Setting up fake worker failed") and PDFs could not be opened for
  measuring. Applies to the web app, the embed frame and the npm library.
- Reproduced with a server that mimics the live MIME table; with the fix a PDF
  opens and renders in **PDF & measurements**. The live site serves the worker
  as `application/javascript`.

## Totals follow the chosen variant — knownbugs 12 and 264

- With variants switched on, the grid, status bar, tail and hours panels,
  header, summary, structure tree, mobile view and wizard total only the active
  variant (and its parent variants). Rows from a variant you did not choose no
  longer count in a post or chapter total.
- **Upgrade note:** in estimates that use variants, displayed totals can be
  lower than in 2026.46.0, because rows of other variants no longer count.
  Without variants nothing changes. Reports and printing still include all
  variants (knownbug 165).

## Review centre: missing prices — knownbugs 11, 13 and 14

- A post with only empty rows beneath it (no quantity, no price, not pro
  memoria) is now flagged as missing a price instead of silently totalling € 0.
- Rows under a post whose own price carries the total (because the rows add up
  to nothing) are no longer flagged.
- A norm row whose rate group is missing from the rate table is flagged; an
  empty rate table falls back to the default rates, as in the calculation.
- The review uses the same variant totals as the grid, so both agree.

## Shared OpenAEC cost profile — #69

- Calc writes the shared `openaec::cost::estimateItem` profile: **IFC data →
  Download (OpenAEC IFCX)**, or `export_ifcx` with `profile: "openaec"` over MCP.
  One item per top-level post with its rolled-up amount, active variant, direct
  costs only. Items from the IFCX Explorer keep their path, quantity reference,
  model links, source rate and status.
- Free items without a model quantity carry their quantity inline as
  `{ value, unit, formula? }`, on import and export. A lump sum without a
  quantity is written as 1 `post`.
- Proposed shared contract: [IFCX interoperability](../ifcx-interoperability.md).
  The full Calc IFCX export (`ifcx::cost` / `ifcx::ocs`) is unchanged.

## Tooling

- `scripts/version.mjs` also reads and writes `src-tauri/Cargo.lock` on a
  Windows checkout with CRLF line endings.

## Evidence and limits

1,567 application tests passed; the remaining failures are a known line-ending
check on Windows checkouts and timing limits of the ÖNORM import tests under
full parallel load (they pass when run alone). The web fix was verified in a
browser against a server with the live MIME table, and on the live site after
deployment. The shared export was verified in the app: the sample estimate gave
6 items totalling EUR 28,109.00, equal to its direct costs, and the file opens
again with the same amount.

Not certified by this release: real SuperCloud end-to-end acceptance (#73;
handover in the issue), anonymous container download (#35, GHCR package still
private by organisation policy), production accounts (#42) and the remaining
findings in `knownbugs.md`.
